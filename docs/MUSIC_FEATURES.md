# 播放、推荐与本地入库增量

本轮实现对应 fnmusic-ext 2.9.0 的播放音质、下载品质、搜索、推荐、公共歌单和存储功能。当前属于本地开发验证版本，未进行真实 fnOS、网易云账号和官方 App 的端到端验收。

| 功能 | 当前实现 |
| --- | --- |
| 播放音质 | 高音质、平衡、流畅三种顺序；只尝试服务端为当前音源账号授权的档位，失败降档 |
| App 下载 | 跟随 App、原文件、MP3 320k；prepare/status/file/delete，支持 HEAD 与 Range；未知官方任务透传 |
| 搜索 | 本地结果优先；在线结果去重、过滤后继续取页；探活、超时、深分页开关和页数上限 |
| 推荐 | 热歌榜、每日推荐；按飞牛用户、音源账号与配置版本隔离缓存；注入只读歌单 |
| 公共歌单 | 排行榜、推荐、分类、精品；勾选、排序、移除、保存与只读注入；精品使用游标分页 |
| 边听边存 | 播放时启动后台完整下载，完成后落库；切歌续传并行数可配，0 表示随播放请求中断 |
| 滚动缓存 | 默认每位用户和音源组合保留 2 首；清理旧文件；队列最多 1000 条，单个源文件最多 512 MiB，下载字节与已完成缓存有 2 GiB 额度；转码临时文件可能增加瞬时占用 |
| 完整性 | HTTP 长度与完整续传范围校验、音频签名检查；有 FFmpeg 时增加完整解码检查；固定续传档位，拒绝截断结果 |
| 封面与歌词 | 完整音频保存后嵌入封面、写入歌曲标签，生成同名 `.lrc`；失败原因显示在任务中 |
| 目录 | NAS SDK 目录选择、手动路径、实际写入检查；可选系统 sqlite3 只读查询官方共享曲库，并兼容共享目录链接探测；多个候选时要求手动选择 |
| 收藏与歌单 | 在线收藏即时保存；官方自建歌单内的在线曲目映射；后台下载、等待官方收录、原用户身份写回；绑定超时与重试；取消收藏同步清除绑定映射 |
| 任务与设置 | JSON 原子持久化、异常中断续传、配置热更新、进度、取消、失败重试；任务重试也会重试待完成绑定 |

## 管理页面

新增“播放与搜索”“推荐歌单”“存储设置”“下载任务”，沿用原有主题和窄窗口适配。修改设置后需要点击“保存设置”；离开设置区域时会提示未保存修改。

所有设置、任务和目录管理接口均要求飞牛管理员身份；写入沿用同源 JSON 管理请求校验。官方音乐 App 的收藏与下载操作使用原用户登录态，不使用管理面板身份代写。

## 默认值与数据

- 自动保存、收藏自动绑定、推荐和公共歌单默认关闭；自动封面默认开启，歌词默认关闭。
- 播放默认高音质；下载默认跟随 App；搜索超时 15 秒，深分页最多 10 页，探活默认关闭。
- 绑定等待 120 秒，下载并行数 3。任务进程内最长执行 10 分钟，中断后可重试。
- 设置位于应用数据目录的 `music-settings.json`；任务在 `audio-jobs.json`；收藏映射在 `collections.json`。登录凭证不写入这些文件。
- 缓存选定目录下使用私有 `.fnmusic-go` 工作目录；Linux 使用 `openat/O_NOFOLLOW` 固定目录与拒绝符号链接替换。共享目录本身权限不改动。
- 更换缓存目录会把去重引用写入新目录的 `saved-index.json`，任务注册表仍保留在应用数据目录；旧音频不自动迁移。目录变化前需要完成或取消正在执行、排队的任务。
- 下载到曲库时使用临时文件和不覆盖现有文件的原子发布。已保存文件不会因为取消任务、缓存清理而被删除。

## 实现与验收边界

边听边存采用独立的后台完整下载请求，播放流继续直接转发；首次播放会额外请求音频，后续可复用完整缓存。与上游在播放流中直接 tee 音频的实现方式不同。

MP3 转码和封面嵌入依赖设备可用的 FFmpeg；未捆绑额外二进制。管理页会显示能力状态，并在启用相关策略时检查。无 FFmpeg 时仍可播放和缓存，完整性检查限于传输长度、范围与格式签名。

收藏绑定通过官方搜索 API 精确核对已保存路径、标题与歌手，再调用官方收藏/歌单写入 API；不修改官方音乐数据库。可选曲库重扫接口仅允许 `/music/api/v1/` 下路径。官方歌单写入额外核验当前用户拥有该歌单；未知字段结构时拒绝写入，需实机核对版本差异。

用户凭证只在内存保留 30 分钟。重启或会话过期后，待绑定记录和音频保留；原用户重新打开收藏/歌单后可重试已下载记录，读取列表不会启动新的下载。管理面板不能代替原用户重新登录。

尚未验证真实设备的官方曲库扫描、目录选择器、播放/下载协议及音源返回差异。不会把本地模拟服务和容器通过结果视为实机通过。

## 播放兼容性核对（0.5.8）

当前具备在线直流 `/track/stream`（GET/HEAD/Range）、音质逐级回退、完整缓存复用和后台缓存/入库，以及单独的 App 下载 prepare/status/file/delete 流程、MP3 320k 文件转码。文件下载转码不等于实时播放转码。

对照原项目 `proxy/app.py` 的播放流程，0.5.8 当时缺失（0.5.9 已实现，见下节）：

- `/track/transcode` 播放准备接口。
- `/track/hls/{guid}/preset.m3u8`、初始化段与 AAC/fMP4 分片传输，以及不经过 prepare 时的惰性启动。
- `/track/transcode/heartbeat`、`quit` 和播放会话回收。
- 源站真实编码与客户端元数据协调；`internal/fnmusic/track.go` 当前仍固定声明 MP3，而高音质直流可能返回 FLAC 等源文件。

因此只验证直流/下载不足以宣称飞牛音乐所有播放模式均兼容。客户端走标准档 HLS 或格式不受支持时，现有透明转发会把在线虚拟 ID 交给不识别它的官方服务；需补齐上述流程并做真实客户端验证。此差距与“歌单详情为空”是不同链路，0.5.8 修复的是歌单批量详情与封面，不包含上述播放转码功能。

参考： https://github.com/javycoder/fnos_music_ext/blob/main/proxy/app.py （track_transcode、track_hls、track_transcode_session、stream_track）。

## 0.5.9 播放转码与格式元数据

- 实现 `/track/transcode`（GET/POST）、`/track/hls/<guid>/preset.m3u8`、初始化段和 fMP4 分片，后端授权取流后以 stdin 向 FFmpeg 输入，输出 AAC 128k / 44.1kHz / 双声道，4 秒分片。支持直接请求 m3u8 惰性启动及已完成音频缓存优先。标准 HLS 同时触发既有后台缓存/边听边存策略。
- heartbeat / quit 按用户、当前音源作用域、歌曲、音质与设置版本隔离；退出终止子进程并删除文件。默认最多 2 个运行中的转码、90 秒空闲回收、512 MiB 总工作目录预算，定期回收失败会话；应用退出全部停止并清理。转码最长 2 小时，输入上限 512 MiB。
- m3u8、初始化段、分片支持 GET/HEAD，分片支持 Range/If-Range；不暴露本机路径或输入 URL，拒绝任意文件名。M4A/MP4 遇到尾部 moov 时先在私有目录限量暂存，以支持解码器寻址。
- 不再给所有在线歌曲硬编码 MP3/320k。音频详情按当前播放音质探测前 512 字节，识别 FLAC/MP3/AAC/MP4/Ogg/WAV 并记录实际文件总长度；未知格式/未知编码保持空值，不虚报采样率和码率。MP4 容器内编码尚未探测时不假定 AAC（也可能为 ALAC）。
- NAS 需要可用且支持 AAC/HLS/fMP4 的 FFmpeg；缺失、音源不可用、转码失败或等待超时返回明确失败，不伪装 ready。官方本地曲目保持透传。

本地真实 FLAC→AAC/fMP4、尾部 moov 的 ALAC/M4A→HLS、ffprobe 编码核验、完整路由、HEAD/Range、心跳/退出、用户隔离、空闲/容量回收及异常输入测试通过。实际飞牛 App/Web 端的端到端播放仍需设备验收。

## 封面持久化缓存与清理

“存储设置 → 封面缓存”支持选择 NAS 目录、手动填写和检查可写性，留空使用应用数据目录。图片实际保存在独立的 `.fnmusic-covers` 子目录；更换目录后使用新位置，不自动迁移或删除旧目录。

歌曲与歌单封面都在验证当前用户、音源及歌单可见性后读取缓存。缓存按用户、音源实例和封面身份隔离，重启后可用；7 天后尝试刷新，源站失败时可继续使用已校验的旧图。单张图片限制 6 MiB，总缓存限制 256 MiB / 2000 项，超出时淘汰最旧的记录。缓存写入失败不阻止已下载图片返回客户端。

页面显示当前生效路径、文件数及磁盘占用。管理员确认清理后，只删除当前已保存目录中扩展生成的常规缓存文件，不递归删除目录、不跟随符号链接。未保存设置时禁用清理，进行中的下载不会在清理结束后重新写回缓存。清理接口沿用管理员身份和管理写请求校验，不接受客户端指定删除路径。

已验证缓存重启命中、过期源站失败回退、用户隔离、容量淘汰、清理保留用户文件/符号链接、并发清理、目录保存和权限校验。Computer Use 在本地 Linux 接口测试页验证了清理、目录检查、保存及刷新后的持久化；真实 NAS 目录选择器和安装后的行为仍需设备验收。

### 网易封面缩略图

歌曲、歌单封面接口的 `size=160` 会传入原生网易和 MusicBox 适配器，对网易图片 CDN（`music.126.net` 及其子域）转换为 `param=160y160`；保留 URL 中其他查询字段，不向其他图片域名添加网易专用参数。缺少 size 或 size=0 保留原图，正数尺寸最大为 2048，非法/负数请求返回 400。

磁盘缓存按请求尺寸分开，并使用新的缓存键版本，避免已保存的原图被当作缩略图返回。实测同一封面原图 1500×1500 / 399844 字节，歌曲与歌单的 160 尺寸均为 160×160 / 20323 字节；测试还覆盖 600 尺寸、不同尺寸缓存隔离、旧缓存隔离以及详情回退链路。

## 稳定性与加载优化

- 诊断：按 DNS、超时、TLS、HTTP 状态、非公网地址拦截、存储权限/空间等类别记录结构化日志；只输出操作名、错误类别和资源哈希，不输出凭证、URL 或上游正文。相同失败短期限频，保留有界计数与最近事件，管理员可读 `/app/fnmusic-go/api/diagnostics`。封面命中/未命中/旧图回退以及缓存和任务状态写入失败均有记录。
- 请求合并：相同用户、音源、封面及尺寸的并发请求共享下载；单个请求取消不影响其他等待者，全部取消后停止下载，封面源站下载并行数最多 4。歌单元数据按用户、音源、配置版本短期复用 15 秒，同页曲目请求也合并。用户身份只在同一个 HTTP 请求内复用，不跨请求缓存；配置关闭歌单后不会复用旧版本列表。
- 大歌单：原生网易按请求窗口取歌曲详情，每批最多 100 首；保留歌单顺序，缺失条目标为不可用。返回总数来自完整 trackIds，移除原先前 1000 首截断；单歌单最多 10000 首，超过安全边界明确报错。`size=-1` 返回完整列表，不再被网关截成 1000 首。MusicBox 不再在 Go 侧截断已有返回，但实际完整性仍取决于桥接服务返回的数据。
- 任务持久化：写入失败时在现有任务警告中标注尚未保存，后台定期重试，成功后解除警告；任务错误使用固定说明和诊断类别，避免将带凭证的网络错误透出。
- 封面存储：新缓存为图片原始字节加 16 字节时间头，不再做 Base64 编码；兼容读取旧 JSON 文件并逐项迁移。正常写入维护增量容量统计，按需/定期扫描，超限时才进行淘汰排序；清理和切换目录仍保持隔离。

## 播放失败诊断与完整 HLS 清单

- 原生网易云与 MusicBox 桥接的 CDN 音频请求统一携带浏览器 User-Agent，保留 Range/If-Range，不向 CDN 转发账号 Cookie。
- 播放失败响应新增脱敏 `diagnostic`：`stage`（source/read/probe/spool/storage/start/transcode）、`reason`，FFmpeg 异常退出时附 `exit_code`。日志仅记录错误类别、退出码和哈希资源标识；FFmpeg stderr 最多在内存保留 8 KiB 供分类，不输出原文、URL、路径、Cookie 或响应内容。
- 未识别的音源内容与 FFmpeg 明确报告的加密错误分开。未知内容不能证明音流加密；可能是错误页面、损坏音频或不支持格式。此流程未添加解密能力，也不绕过账号权限。
- 准备接口与 m3u8 请求等待整首转码完成后才提供完整 VOD 清单，避免只请求一次清单的客户端拿到前几片后提前结束。与按元数据猜测未来分片不同，此方式仅交付已生成的真实分片；首次播放需要等待整首下载及转码，仍受每次请求 30 秒上限约束。等待超时返回 504，后台会话继续完成，可在空闲回收前重试复用。
- 真实设备上的歌曲 3445490637 尚未复测，新增分类不能作为该歌曲实际失败原因的证据。

## 原生网易云 EAPI 登录上下文

- EAPI 加密请求体的 header 与 HTTP Cookie 同时携带 MUSIC_U（或匿名 MUSIC_A）、NMTID、CSRF 和设备上下文，客户端信息与 EAPI User-Agent 对齐 MusicBox 所用协议。WEAPI 扫码仍使用独立浏览器上下文，账号凭证不传给音频 CDN。
- source 阶段的 HTTP 拒绝按环节区分：netease-api-http-403、musicbox-api-http-403、media-cdn-http-403；网易云 JSON 业务 code=403 单列 netease-api-code-403。每档音质失败分别记录脱敏诊断，不再只能看到最后一档的结果。
- 本地请求解密断言、账号隔离、CDN 凭证隔离及各环节拒绝请求的测试通过；尚未在 NAS 验证实际 403 是否消失。
